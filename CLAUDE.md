# Nexus DNS — контекст для Claude

Свой DNS на зарубежном VPS: режет рекламу (особенно в мобильных играх) и пускает Gemini/ChatGPT/
Claude из РФ через SNI-прокси. Пока для семьи и друзей владельца, дальше — функция Nexus (VPN-сервис,
репо Rklm-it/vgx3d). Устройство и сценарии — в `README.md`.

**Главное требование владельца:** один адрес для всех, вписал один раз — и работает всегда. Никакой
регистрации устройств, профилей, персональных адресов. Новая фича не должна требовать от человека
второго шага на телефоне.

- AdGuard Home (DNS) + nginx: stream на 443 (SNI) → http-сервер для `dns.домен` (страница, DoH,
  панель `/admin/`) и внутренний прокси для ИИ. Утилита `nexusdns/` — только stdlib.
- `nexus-dns lists build` собирает российские правила `$third-party` и `podkop-block.txt`;
  `nexus-dns-update.timer` раз в сутки: git pull main + build + apply — так правка доезжает до парка.
- `install.sh` — установка и обновление (идемпотентен). `nexus-dns apply` — состояние из `lists/`.
- Домен у любого регистратора, сертификат на одно имя по HTTP-01 (порт 80). Cloudflare — по желанию.
- Тесты: `pip install -e ".[dev]" && pytest -q`. Тест nginx `-t` идёт, если nginx установлен.
- Пользователь пишет по-русски — отвечать, комментировать и логировать по-русски.

## Инварианты

Каждое правило проверено на живом AdGuard Home v0.107.79 и nginx 1.24, а не взято из документации.

1. На негодный сертификат `tls/configure` отвечает **200 и ничего не применяет**: причина есть только в
   `warning_validation`. Проверять `valid_pair` в ответе (`apply.configure_tls`).
2. Список прокси — один источник для правил AdGuard Home и карты nginx (`lists.py`). Домен, который DNS
   ведёт на сервер, а nginx не пропускает, — тихо мёртвый сайт. Сторож — `test_proxy_list_same_in_dns_and_nginx`.
3. В `map … { hostnames; }` у nginx `.домен` уже покрывает голый домен. Строка с голым доменом рядом —
   «conflicting parameter», и nginx не стартует. Значит, 443 лёг у всех.
4. Доступ открыт: `allowed_clients` пуст (= пускать всех), `apply.open_access`. Если когда-нибудь его
   закрывать — `127.0.0.1` туда нельзя никогда: весь DoH приходит от nginx с loopback.
5. Лимита запросов по IP нет (`ratelimit: 0`): под VPN все пользователи ноды приходят с одного IP выхода.
6. `resolver` в nginx — публичный (1.1.1.1), не наш AdGuard: тот вернёт на домен из прокси наш же IP,
   и nginx зациклится сам на себя.
6а. Шлюз шлёт PROXY protocol на ВСЕ внутренние переходы (`proxy_protocol on` в stream не бывает
   «по условию»), поэтому прокси ИИ идёт через второй stream-сервер на 127.0.0.1:8446, который его
   снимает. Прямой `proxy_pass $ssl_preread_server_name:443` из первого сервера отправил бы
   заголовок PROXY самому Google. Без PROXY protocol DoH видит 127.0.0.1 вместо человека.
7. `$dnsrewrite=<IPv4>` отдаёт A = IP сервера и пустые AAAA/HTTPS — так и нужно. AAAA увёл бы телефон
   мимо прокси, а HTTPS-запись дала бы ECH и чужой внешний SNI.
8. Правила AdGuard Home перечитывает в фоне 1–2 с после `set_rules`: проверка сразу после `apply` видит
   старое. `selfcheck` повторяет попытки.
9. Под белыми списками без VPN зарубежный DNS недоступен, и строгий Частный DNS Android = «нет
   интернета». С VPN работает (DNS в туннеле), но только если VPN знает сервер по IP: домен ему до
   туннеля резолвить нечем. В Nexus это `cdn_address` у CDN-строк подписки.
10. Мастер первого запуска AdGuard Home — только на 127.0.0.1 (`--web-addr`): на внешнем адресе сервер
    настроил бы первый, кто зайдёт. Порт 3000 в `install/configure` тот же, что у мастера, — так можно.
11. Стоковый сайт nginx (`listen [::]:80`) без IPv6 не стартует и роняет даже `apt install nginx`.
    Установщик его убирает: серверу DNS он не нужен.
12. Gemini через выход VPN-ноды Google режет 429 («У Gemini сейчас перерыв»), через IP DNS-сервера — 200
    (проверено 25.10.2026 с роутера владельца). С podkop — снять список «Google AI», и `proxy.txt` обязан
    покрывать весь `itdoginfo/allow-domains/Services/google_ai.lst`, кроме `clients6.google.com` целиком.
    «Регион недоступен» сразу после «Сохранить и применить» в podkop — окно перезапуска (DNS провайдера),
    а не наш DNS: сначала журнал, есть ли там вообще запросы к этим доменам.
13. AdGuard Home НЕ берёт правила с `$third-party` (DNS не знает, чей это сайт) — молча. В RU AdList их
    большинство: из 5 634 новых доменов работал 1 183. Перевод в обычные — только в `build.py`, без
    популярных сайтов (Tranco) и `lists/protect.txt`.
14. Исключение `@@` в чужом списке перебивает нашу строку в `block.txt`, тоже молча (так было с
    `app.adjust.com`, `cdn.taboola.com`). `nexus-dns status` сверяет, что весь `block.txt` блокируется.
15. Локальный список AdGuard Home берёт только из `/opt/AdGuardHome/userfilters/` (`safe_fs_patterns`).
    `apply` с другой машины (через API) снимет такие списки как «лишние» — применять только на сервере.
16. В podkop-список не класть сам домен из списков podkop (facebook.com), только поддомены: человек
    завёл домен в VPN, чтобы им пользоваться. Рабочие (graph.facebook.com, googlevideo.com, t.me…)
    сверены руками 25.10.2026 — правило отбора не трогать без такой же сверки.
17. Формы входа на публичном домене быть не должно: 25.10.2026 Chrome показал на dns.nex-most.ru
    «Опасный сайт» (публичная база Safe Browsing при этом чистая — это проверка в браузере). Панель —
    за `auth_basic` nginx; AdGuard Home принимает тот же заголовок Authorization, второй раз не
    спрашивает. Файл пароля — в `/etc/nginx/nexus-dns/` 640 root:www-data: из `/etc/nexus-dns` (700)
    воркер nginx его не прочтёт, и вместо панели будет 500.
18. Свой «Частный DNS» на телефоне за роутером с podkop ломает podkop: телефон спрашивает наш DNS
    напрямую, podkop не видит имени и шлёт сайт мимо VPN. YouTube (в podkop только домены) — напрямую
    и под ТСПУ; Telegram и Instagram живут (у podkop есть их подсети). Дома — «Автоматически».
    `s.youtube.com` режет RU AdList Counters — он в allow.txt, ключевые домены YouTube — в protect.txt
    точными адресами (родитель youtube.com там убрал бы ads.youtube.com из podkop-списка).

# Nexus DNS

Свой DNS-сервер на VPS. **Один адрес для всех**: человек один раз вписывает его в телефон
или роутер, и дальше ничего делать не нужно. Сервер делает три вещи:

1. **Режет рекламу**, в первую очередь в мобильных играх: AdMob, Unity Ads, AppLovin,
   ironSource, Mintegral, Pangle, Яндекс и другие рекламные сети. Заодно режет рекламу и
   слежку самих телефонов (Realme/OPPO, Xiaomi, Samsung, Huawei) и российскую рекламу
   (Директ, myTarget, RU AdList).
2. **Защищает**: фишинг, вредоносные сайты, мошенничество, майнеры (HaGeZi TIF).
3. **Открывает Gemini, ChatGPT, Claude и другие ИИ из РФ** без VPN. DNS отдаёт на их домены
   IP сервера, сервер пропускает соединение к настоящему сайту, и сайт видит зарубежный IP.

```
телефон ──DoT :853──────────────► AdGuard Home (блок-листы)
        ──:443──► nginx stream (смотрит имя сайта, не расшифровывает)
                   ├─ dns.домен ─► nginx http: страница, профиль iPhone, список для podkop,
                   │               /dns-query → AdGuard Home (с настоящим IP), /admin/ → панель
                   ├─ домены из lists/proxy.txt ─► внутренний прокси ─► настоящий сайт (Gemini…)
                   └─ всё остальное ─► сброс (это не открытый прокси)
```

Внутри — [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome) и nginx. Утилита
`nexus-dns` (Python, только stdlib) приводит их в нужное состояние по файлам из `lists/`.

## Что нужно

- **VPS за границей** в стране, где работает Gemini (Европа, США, Великобритания…). Хватит
  1 ядра и 1 ГБ. **Не на ноде Nexus:** там 443 занят Reality, а шлюзу DNS нужен весь 443.
  После аренды проверь, что IP пингуется из дома без VPN: заблокированный IP не спасти.
- **Домен у любого регистратора** (или поддомен уже имеющегося): `dns.example.com`.
  Нужна одна A-запись «`dns.example.com` → IP сервера». Если домен в Cloudflare, можно дать
  токен (права Zone.DNS Edit + Zone Read), и установщик создаст запись сам. Если нет — впишешь
  её руками у регистратора, установщик подождёт. Лучше .com/.net/.org, чем .ru.
- **Порт 80 открыт снаружи** — по нему Let's Encrypt проверяет домен при выдаче сертификата.

## Установка

```bash
git clone https://github.com/Rklm-it/nexus-dns /opt/nexus-dns
sudo /opt/nexus-dns/install.sh
```

Установщик спросит домен, токен Cloudflare (можно пропустить) и почту, а потом сделает всё сам:
- дождётся A-записи;
- выпустит сертификат;
- поставит файрвол;
- поднимет AdGuard Home и nginx;
- соберёт списки, применит их и проверит сервер снаружи;
- включит автообновление раз в сутки.

Повторный запуск — обновление, настройки он помнит (`/etc/nexus-dns/nexus-dns.env`).

## Что вписать на устройствах

Адрес один для всех, без регистрации устройств. Всё это есть на странице
**`https://dns.example.com/`** — её и отправляй людям. Подсказка на сервере — `nexus-dns howto`.

| Где | Что вписать |
|---|---|
| Android 9+ | Настройки → Подключение и общий доступ → **Частный DNS** → Имя хоста: `dns.example.com` |
| iPhone, iPad, Mac | профиль одним касанием: `https://dns.example.com/nexus-dns.mobileconfig` → Настройки → Профиль загружен |
| Браузер, Windows 11 | DoH: `https://dns.example.com/dns-query` |
| Роутер (OpenWrt, Keenetic…) | DoT `tls://dns.example.com` или DoH-ссылка — и все устройства дома защищены сразу |

## Роутер с podkop

LuCI → Службы → Podkop → вкладка «Настройки»:
- **Тип протокола DNS** → `DNS через TLS (DoT)`;
- **DNS-сервер** → `dns.example.com`;
- **Bootstrap DNS-сервер** → `77.88.8.8`.

**Реклама внутри VPN-списков podkop.** Домены из списков podkop (Russia inside, Meta,
YouTube…) до нашего DNS не доходят: podkop отвечает на них сам и шлёт в туннель. Поэтому
`an.facebook.com`, `ads-api.tiktok.com`, `ads.youtube.com` проходили бы. Сервер сам собирает
их список (то, что наш DNS режет внутри списков podkop) — подключи его один раз:
«Секции» → добавить секцию → **Тип подключения: Block** → «Внешние списки доменов» →
`https://dns.example.com/podkop-block.txt`.

Ещё во вкладке «Секции» → «Списки сообщества» **сними «Google AI»**. Пусть Gemini идёт
через этот сервер, а не в VPN. Выход VPN-ноды Google часто режет ответом 429 («У Gemini
сейчас перерыв»), а чистый IP DNS-сервера — нет. Домены из списков podkop до нашего DNS
не доходят: podkop отвечает на них сам и шлёт в туннель.

После «Сохранить и применить» podkop перезапускается и на эти секунды возвращает DNS
провайдера. Телефон может запомнить настоящий адрес сайта и пойти напрямую — отсюда
внезапное «недоступно в вашем регионе». Подожди 2–3 минуты, включи и выключи режим полёта,
перезапусти приложение.

## VPN и белые списки

| Ситуация | Работает? |
|---|---|
| Wi-Fi, мобильный интернет | да |
| **Любой VPN включён**, в том числе для обхода белых списков | да, ничего менять не надо: DNS идёт внутри туннеля и доходит до сервера даже под белыми списками |
| Белые списки, VPN выключен | нет. Под белыми списками не работает ничего зарубежного, и DNS тоже: Android покажет «нет интернета», пока не включишь VPN или не уйдёшь на Wi-Fi |

Чтобы VPN поднимался под белыми списками с таким DNS, он должен знать свой сервер **по IP,
а не по домену**: до поднятия туннеля найти домен ему нечем. В подписке Nexus это CDN-строки
с закреплённым адресом (`cdn_address`). Если адрес не задан, в ссылку уходит домен CDN.

Лимита запросов по IP на сервере нет: под VPN все пользователи ноды приходят к DNS с одного IP.

## Реклама в играх: чего ждать

- Межстраничная реклама и баннеры из рекламных сетей исчезают: игра пробует показать,
  не получает ответа и идёт дальше.
- **Бонус за просмотр рекламы** («посмотри ролик — получи монеты») без рекламы не выдаётся.
  Это не поломка.
- Редкие игры показывают рекламу со своих же серверов. Такую DNS от самой игры не отличит.
- Если игра или приложение сломалось: открой панель → Журнал запросов, найди красные строки,
  впиши домен в `lists/allow.txt` и выполни `nexus-dns apply`.

## ИИ через прокси

`lists/proxy.txt` — домены, которые идут через сервер (Gemini, AI Studio, NotebookLM,
ChatGPT, Claude, Copilot, Grok). Строка покрывает домен со всеми поддоменами.

- Работает для того, что **сам сайт** не пускает из РФ. **Не помогает** против блокировок
  ТСПУ (YouTube, Instagram): прокси не шифрует. Такие домены `nexus-dns` в список не пустит.
- Сайт открылся не полностью — смотри в журнале, к каким ещё доменам он ходит, и добавь их.
- ChatGPT стоит за Cloudflare. На IP дата-центра Cloudflare иногда показывает проверку
  «вы человек?» — браузер её проходит.
- Для этих доменов DNS отдаёт только IPv4 и пустые AAAA/HTTPS. Иначе телефон ушёл бы по
  IPv6 мимо прокси или включил ECH, и шлюз не увидел бы имя сайта.

## Панель

`https://dns.example.com/admin/` — AdGuard Home: журнал запросов (сутки) с настоящими IP,
статистика (неделя).
Логин и пароль показывает установщик, они же лежат в `/etc/nexus-dns/nexus-dns.env`.
`apply` перезаписывает только свой блок правил и свои списки «nexus:», правила,
добавленные руками в панели, не трогает.

## Что открыто снаружи

| Порт | Что |
|---|---|
| 443/tcp | nginx: страница, DoH и панель для `dns.домен`, прокси для доменов из списка, остальное — сброс |
| 853/tcp, 853/udp | DoT и DoQ AdGuard Home |
| 80/tcp | проверка Let's Encrypt, остальное — переадресация на https |
| 53, 5300, 3000, 8443 | закрыты файрволом (своя таблица nftables, SSH и чужие правила не трогает) |
| 443/udp | отказ: браузер сразу уходит с QUIC на TCP |

Адрес DNS открыт любому, кто его знает: регистрации нет. Атаки через него не усилить
(только TCP: DoT/DoH), а открытого DNS на 53 нет. Если кто-то чужой начнёт грузить
сервер — его IP можно вписать в чёрный список в панели (Настройки DNS → Доступ), `apply`
его не сотрёт.

## Списки

| Файл | Что |
|---|---|
| `lists/filters.txt` | блок-листы по ссылкам: AdGuard DNS filter, HaGeZi Pro и списки телефонов, RU AdList, HaGeZi TIF |
| `lists/block.txt` | свой блок: рекламные SDK игр, Директ, myTarget, майнеры, видеореклама |
| `lists/allow.txt` | исключения, если что-то сломалось |
| `lists/proxy.txt` | домены через сервер (ИИ) |
| `lists/protect.txt` | то, что не должно блокироваться никогда (банки, Госуслуги, маркетплейсы) |

`nexus-dns lists build` собирает ещё два списка из чужих источников:
- **российские правила `$third-party`**: в RU AdList их большинство, а AdGuard Home такие не
  берёт. Переводим в обычные, но без популярных сайтов (Tranco top 20 000) и `protect.txt`;
- **`podkop-block.txt`**: реклама внутри VPN-списков podkop (см. выше).

`nexus-dns status` проверяет, что живые блок-листы не задели `protect.txt`, а исключения
в чужих списках не перебили `block.txt`. Ложное срабатывание видно в тот же день.

## Обслуживание

```bash
nexus-dns status        # проверка снаружи: DoH, DoT, прокси, реклама, сайт, важные сайты, сертификат
nexus-dns apply         # после правки lists/
nexus-dns howto         # что вписать на устройствах
nexus-dns update        # то же, что делает таймер: git pull + lists build + apply
cd /opt/nexus-dns && git pull && ./install.sh                 # обновить всё, включая установку
AGH_UPGRADE=1 ./install.sh                                    # + новая версия AdGuard Home
```

**Автообновление:** `nexus-dns-update.timer` раз в сутки ночью (с разбросом до часа) берёт
`main` из репозитория, свежие списки и применяет. Правка в `main` за сутки доезжает до всех
серверов. Не скачался чужой список — остаются вчерашние файлы. Изменения самой установки
(пакеты, службы) таймер не делает — для них `./install.sh`.

Сертификат продлевает certbot сам, после продления AdGuard Home перезапускается.

## Разработка

```bash
pip install -e ".[dev]" && pytest -q
```

Что проверено вживую на AdGuard Home v0.107.79 и nginx 1.24 (а не только тестами):
- подмена адресов для прокси;
- DoT и DoH по общему адресу;
- шлюз nginx: TLS до настоящего gemini.google.com через сервер, сброс незнакомых имён сайтов;
- секция nginx установщика на системном nginx: проверка Let's Encrypt на :80 и шлюз на :443;
- `apply` повторно и поверх правил человека;
- мастер первого запуска;
- страница, профиль iPhone, список для podkop, панель на `/admin/`, настоящий IP клиента
  в журнале DoH (через PROXY protocol);
- локальный список российских правил в AdGuard Home, HaGeZi TIF (+64 МБ памяти);
- `protect.txt` не задет ни одним списком.

Боевой сервер: dns.nex-most.ru (Lunar Hosting, Нидерланды), с 25.10.2026.
